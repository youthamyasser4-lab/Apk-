# مصاريفنا أوفلاين (نسخة تجريبية قابلة للبناء)

هذه نسخة مبنية على ملف `index.html` القديم الذي يعمل، مع إضافة حفظ محلي ومزامنة معاملات عند عودة الإنترنت.

## الموجود
- واجهة مصاريفنا الأصلية.
- حفظ نسخة محلية من الحسابات والمعاملات بعد تسجيل الدخول والتحميل مرة واحدة بالإنترنت.
- إضافة معاملات بدون إنترنت وتسجيلها في قائمة انتظار محلية.
- محاولة المزامنة تلقائيًا عند عودة الاتصال.
- تمييز المعاملات التي لم تتم مزامنتها بعد.
- قائمة حذف مؤجلة عند عدم الاتصال للمعاملات المحفوظة على الخادم.

## مهم قبل الاستخدام الحقيقي
- هذه نسخة أولية؛ بيانات الكاش وقائمة الانتظار محفوظة في `localStorage` داخل التطبيق وليست قاعدة SQLite مشفرة.
- يجب اختبارها على مشروع Supabase الفعلي وسياسات RLS. المزامنة تفترض أن `transactions.id` يقبل UUID وأنه مفتاح فريد، وهو الافتراض المعتاد لكن يلزم التحقق من مخطط قاعدة بياناتك.
- أول تسجيل دخول وتحميل للحسابات يحتاج الإنترنت. بعد ذلك يمكن فتح التطبيق دون اتصال ما دامت جلسة Supabase محفوظة محليًا.
- لا تضف مفتاح `service_role` إلى التطبيق. المفتاح الموجود في الواجهة هو publishable key.
- الحسابات المشتركة وصلاحيات الأعضاء يجب اختبارها قبل الاعتماد على التطبيق.

## تجهيز APK على جهاز كمبيوتر
1. ثبّت Node.js LTS وAndroid Studio مع Android SDK.
2. فك ضغط الملف.
3. افتح Terminal داخل المجلد وشغّل:
   ```bash
   npm install
   npx cap add android
   npx cap sync android
   npx cap open android
   ```
4. من Android Studio انتظر اكتمال Gradle Sync، ثم اختر Build > Build APK(s).
5. ملف APK التجريبي يظهر عادة داخل `android/app/build/outputs/apk/debug/`.

## ملاحظات
- هذا ZIP هو **مشروع المصدر** وليس ملف APK جاهزًا؛ بيئة البناء الحالية لا تحتوي Android SDK/Gradle project كاملًا لتسليم APK موثوق مباشرة.
- إذا كانت قاعدة بياناتك لا تستخدم UUID في `transactions.id` أو كانت سياسات RLS تمنع إدخال ID من العميل، فيلزم تعديل صغير في طريقة المزامنة.
